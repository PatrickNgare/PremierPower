# SEO — Premier Power Limited

How search is handled on premierpower.co.ke, what was found and changed, and what still needs doing. Audit and changes dated 26 November 2026.

---

## 1. How the site is built (relevant to search)

| Part | What it is |
|---|---|
| Frontend | React 19 single-page app, Vite 8, React Router 7, Tailwind 4, react-helmet-async 3. Hosted on Vercel. |
| Backend | FastAPI + PostgreSQL on Render (`premierpower-api.onrender.com`). Vercel forwards `/api`, `/sitemap.xml`, `/robots.txt` to it. |
| Page tags | `src/seo/pages.js` holds every page's search title and description. `components/Seo.jsx` renders them in the browser. `scripts/seo-html.mjs` writes them into each page's HTML at build time. |
| CMS overrides | CMS → Settings → SEO. A value typed there wins over `pages.js`. A blank field means "use the built-in one". |
| Sitemap / robots | Generated by the API from the CMS (`backend/app/routers/sitemap.py`). |
| Images | Photographs on Cloudinary, delivered as WebP/AVIF at the size the screen needs. |

## 3. What was changed

### Technical
- **Every page now has its own HTML** with its own title, description, canonical, robots, Open Graph/Twitter tags and structured data (`scripts/seo-html.mjs`, run by `npm run build`). Crawlers and link previews no longer need JavaScript to see them. The app removes these on load and renders its own (`src/main.jsx`), so a browser never holds two sets.
- **Real 404s.** Any address that is not a page now returns HTTP 404 (`dist/404.html`) instead of 200.
- **One URL per page.** `trailingSlash: false` redirects `/services/` → `/services`; `cleanUrls` serves `/services` from `services.html` and redirects `/services.html`; `premier-power.vercel.app` redirects permanently to `premierpower.co.ke`. Canonical tags always point at the clean `https://premierpower.co.ke` address, so tracking parameters never create duplicates.
- **CMS kept out of search**: `X-Robots-Tag: noindex` on `/admin`, plus `Disallow: /admin` in robots.txt (unchanged).
- **Sitemap** now includes each service page once it has enough content, every published Insights article with its real publish date, and drops the Reviews page while it has no reviews. The false "changed today" date on every URL is gone.
- **Structured data**: `ElectricalContractor` (with logo, opening hours, address, phone, email, area served), `WebSite`, `BreadcrumbList` on every inner page, `Service` on indexable service pages, `Article` on articles, `FAQPage` on /faq. No ratings, reviews or awards anywhere.
- **Sharing image** (1200×630, Cloudinary) on every page; overridable per page in the CMS.
- **Optional auto-rebuild**: with `VERCEL_DEPLOY_HOOK` set on Render, content edits trigger one Vercel rebuild five minutes after the last change, so new pages get their HTML without a manual redeploy.

### Content structure
- **Home H1** now contains the small label as well as the slogan. The look is unchanged.
- **Service pages** at `/services/<name>` for all eight service lines, from the CMS. Each has a call-to-action box (quote, call, WhatsApp) and links to the other services. **A service page is kept out of search until its description reaches about 100 words (600 characters)**; all eight are currently shorter.
- **Insights section** at `/insights` and `/insights/<name>`, from the CMS (Website pages → Insights articles). It stays out of search until something is published.
- **Contact page**: address in an `<address>` element with a Google Maps "Get directions" link.
- Wrong descriptions inherited from a template ("residential rewiring in Nairobi", "homeowners and landlords") removed.

### Performance
- Slideshow, project, sector and lighting photographs now come from Cloudinary in WebP/AVIF at the screen's size, wherever the CMS still holds the old file path.
- Home page HTML preloads the first slideshow photograph at high priority (the same file the image then uses, so it is fetched once).
- Both main fonts preloaded; early connection to Cloudinary on every page.

### Conversion and measurement
- Google Analytics 4 support, off until `VITE_GA_ID` is set. Tracks page views, `click_call`, `click_whatsapp`, `click_email` and `generate_lead` (enquiry form sent). The CMS is never tracked. No personal data is sent.
- Enquiry form: inline validation, spam honeypot, waking-server notice, success message — see the earlier forms work.

The profile is the main driver of "electrical contractor near me" results and the map pack. Only the business owner can create or claim it.

## 8. Analytics and Search Console

**Google Search Console** (free, essential):
1. https://search.google.com/search-console → Add property → **Domain** → `premierpower.co.ke`.
2. Google gives a TXT record. In the Safaricom portal DNS editor for premierpower.co.ke, add a **TXT** record with name `@` and that value. Don't touch the MX or other records.
   *Alternative*: choose **URL prefix** → HTML tag, copy only the `content` value, add it in Vercel as `GOOGLE_SITE_VERIFICATION`, and redeploy.
3. Once verified: Sitemaps → submit `sitemap.xml`. Then URL Inspection → `https://premierpower.co.ke/` → Request indexing.

**Google Analytics 4**:
1. https://analytics.google.com → create a property for premierpower.co.ke → Web data stream → copy the Measurement ID (`G-…`).
2. Vercel → premier-power → Settings → Environment Variables → `VITE_GA_ID` = that ID (Production) → redeploy.
3. In GA4 → Admin → Events, mark `generate_lead`, `click_call` and `click_whatsapp` as key events.
4. Link GA4 to Search Console (Admin → Product links) to see search queries next to visits.
5. Kenya's Data Protection Act 2019 applies to analytics cookies. Consider adding a short privacy notice to the site before switching analytics on.

## 10. Monthly routine

1. **Search Console → Performance**: which queries bring impressions and clicks; note pages with many impressions but low click-through and improve their title/description in the CMS.
2. **Search Console → Pages**: fix anything "Not indexed" that should be.
3. **GA4**: enquiries (`generate_lead`), calls and WhatsApp taps by page and by source.
4. **Publish one or two Insights articles** on questions clients actually ask. Link each to the relevant service page.
5. **Add one or two finished projects** with good photographs and a short write-up naming the type of building and the work done.
6. **Google Business Profile**: new photos, reply to reviews, a post about recent work.
7. Every quarter: run https://pagespeed.web.dev/ on the home, services and contact pages; check links still work.

## 11. Deploying

Push to `master`. Vercel runs `npm run build`, which runs `vite build` and then `scripts/seo-html.mjs`. The script reads the live API (`SEO_API`, default `https://premierpower-api.onrender.com/api`) and allows 90 seconds for the free Render plan to wake. If the API can't be reached, the fixed pages are still written from `src/seo/pages.js` and the build succeeds; per-service, per-product and per-article HTML waits for the next build. Backend changes deploy on Render from the same push.
